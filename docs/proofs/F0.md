# F0: the five proofs

F0 is done when every proof below has a written result with numbers ([ROADMAP](../ROADMAP.md)). Three are passed. Two are ready on the Mac side and wait for steps only the author can take: the phone (d) and the Claude app (e).

| Proof | Result | Key numbers | Details |
|---|---|---|---|
| (a) 16 visible terminals with continuous agent-like output | **Passed** | 16 panes at 1512x982 replaying a real Claude Code session. Default config (hybrid, 4 WebGL): keystroke echo p50 / p95 / p99 15.5 / 18.5 / 20.5 ms, 0.01% dropped frames, 0 missed keys, about 1.6% of a core for renderer, GPU and main together. At 4x replay speed: echo p95 23.2 ms, 0.28% dropped. Pass bar: echo p95 ≤ 50 ms and ≤ 5% dropped frames | [F0-a.md](F0-a.md) |
| (b) 10 live sessions survive quitting, `kill -9`, a rebuild and reopening the app | **Passed** | 10/10 sessions alive with the same pids after each of the three, and every restored screen shows the counter advanced. Host level: attach with scrollback 2000 serializes in 4.3 ms (p50); echo round trip p50 / p95 2.49 / 2.92 ms idle and 2.97 / 6.03 ms with another session flooding output | [F0-b.md](F0-b.md), [F0-b-headless.md](F0-b-headless.md) |
| (c) drag a worktree to a pane edge, save and restore the layout | **Passed** | 3 consecutive e2e runs 4/4, `--repeat-each=12` 36/36; layout identical after a relaunch | [F0-c.md](F0-c.md) |
| (d) PWA on an Android phone over Tailscale: open a session, type, push while locked | **Pending the phone** | Mac side (e2e on the Galaxy S25+ screen in Chromium, real `tailscale serve` from the Mac): pairing and cookie through the tailnet URL, WS open 28 ms, input echo 10 ms locally, BEL to push request 15 ms locally, offline shell opens with Tailscale off and reconnects by itself. Still to measure: the locked-phone push delay over FCM (target for F3: within 10 s) | [F0-d.md](F0-d.md) |
| (e) answer a Bancada-hosted Claude session from the Claude app with `--remote-control` | **Pending the Claude app** | `claude --remote-control` runs in a pty-host session and registers a Remote Control session; answering it from the app is the last step | [F0-e.md](F0-e.md) |

The replay harness that feeds (a) is described in [F0-replay.md](F0-replay.md): the real recording is 81.6 s, 44.5 KB, about 0.5 KB/s on average with peaks near 12.5 KB/s, and is kept private.

## Known gaps carried into F1

- Closing a panel does not end its session yet: sessions stay in the host until something kills them.
- After a window reload (Cmd+R, or HMR in dev) the main process may keep the old views attached, because it only drops them when the window is destroyed (found by reading the code, not reproduced).
- The (a) bench could not tell the renderer configs apart at this load; the hybrid default with 4 WebGL terminals comes from a rule (bounded contexts, smallest budget within noise), not from a measured win.
- The pty-host test teardown kills any `bancada-t-*` host on the machine, so two worktrees running the tests at the same time can break each other's runs.
- Log rotation, cleanup of old runtime dirs, a board backup when a restore fails, discovery of unreadable folders and symlinks, and seed validation in the replay generator.
